## English summary

This dossier prepares a 3 AImigo episode on agents as users of products and open-source projects (cut-off: 31 October 2026). Agents already generate a large share of activity: GitHub's Octoverse (28 October 2026) reports that more than 40% of pull requests started from a detectable agent's first draft by September 2026, while Neon and Honeycomb report agents creating most databases or about a fifth of queries. Product owners respond in two directions: making products legible to agents (Markdown on request, MCP servers, skills, anonymous deploys, AXIS evaluations) and governing intake (nine GitHub controls from February to October 2026, collaborator-only repositories, Hacktoberfest dropping PR rewards). Evidence against the hype: major crawlers almost never fetch llms.txt, Google calls special AI files unnecessary, and the Ninth Circuit treated an agentic browser as the user's tool under anti-hacking law. Most numbers are vendor telemetry; independent measurement of agent experience remains thin.

## Главный тезис и угол выпуска

**Тезис.** Агент приходит в продукт не как новый вид клиента, а как новый вид трафика с чужими полномочиями. Выигрывает не тот, кто положил на сайт «файл для ИИ», а тот, кто, во-первых, даёт агенту короткий машинный контракт (документацию в Markdown, компактные инструменты, вход без ручного онбординга) и измеряет, доходит ли агент до цели, а во-вторых, дозирует вход по доверию и истории участника, а не по признаку «это написал ИИ». Оба направления видны в данных за 2026 год: GitHub считает, что больше 40 % PR начинаются с черновика агента [1], и одновременно выпустил девять настроек для ограничения входящего потока [3]–[7]; Cloudflare по запросу отдаёт агентам Markdown [29] и одновременно делит агентов на «прямых» и «посредников», чтобы сайт мог решать, кому доверять [15].

**Почему сейчас.** Июль–октябрь 2026 года сдвинули тему из прогнозов в настройки по умолчанию. 1 июля Cloudflare включила подписанных агентов в программу проверенных ботов [15]. 10 июля Google в руководстве для владельцев сайтов прямо написала, что специальные машиночитаемые файлы для её поиска не нужны [17]. 28 июля вышла версия MCP 2026-07-28 без сессий и с заголовками для шлюзов и ограничителей частоты [13]. 4 августа апелляционный суд назвал агента браузера инструментом пользователя [18]. В октябре Hacktoberfest перестал засчитывать PR [11], Cursor открыл маркетплейс приложений для собственного хостинга кода, «спроектированного под масштаб агентов» [55], [56], Anthropic передала Agent Skills в Agentic AI Foundation [52], а 28 октября GitHub опубликовал Octoverse [1] и разрешил освобождать от лимитов PR по возрасту аккаунта и истории слияний [5].

**Что нового относительно S1E1–S1E12.** S1E10 обсуждал агента покупателя, которому человек делегирует платёж; S1E9 — сколько работы можно доверить агенту; S1E2 — почему поставка не ускоряется. Здесь та же картина с другой стороны: владелец продукта или мейнтейнер, к которому агент пришёл. В S1E10 прозвучала затравка для выпуска — пересказ о том, как основатель Vercel просит прислать, что сказал агент, и чинит сценарий [40]; в S1E2 — история о внутренних API, которые для агентов отдают мегабайтные JSON [41]. Этот выпуск может превратить обе истории в практику.

**Что не повторять.** Мандаты AP2, правила Visa и ACP (S1E10 и T3); горизонты METR (S1E9); внутренние ярусы риска при слиянии в Claude Code (лонгрид об инфраструктуре и T4). Передачу Agent Skills в фонд и маркетплейс Cursor уже упомянул дайджест S1E12, а Origin — дайджест S1E3 — здесь это не новости, а свидетельства сдвига. Доля 40 % и 110 млн агентских PR из Octoverse уже приведены в лонгриде к октябрьскому дайджесту (в самом эфире S1E12 их не называли); новое здесь — сравнение доли слияний и угол внешнего входа. Мейнтейнерский поток мусора уже был в лонгриде об инфраструктуре (§7); новое — октябрьские правила GitHub, Octoverse и Hacktoberfest.

## Позиции и спорные места

**Лагеря.**

1. **«Агент — новый первоклассный пользователь».** Netlify ввела термин AX — «the holistic experience AI agents will have as the user» [39], сделала вход для агентов netlify.ai [38], анонимный деплой [37] и инструмент оценки AXIS [35]. Cloudflare призывает «start to treat agents as first-class citizens» [29]; Stripe отдаёт документацию в Markdown, MCP-сервер и каталог навыков [31]. Сильнейшая опора лагеря — телеметрия Neon (80 % баз) [12] и Honeycomb (≈ 20 % запросов) [13].
2. **«Агент — инструмент человека, а не пользователь».** Апелляционный суд: доступ осуществляет пользователь, агент — инструмент [18]. GitHub: за машинный аккаунт отвечает владелец-человек [19]. Google: оптимизация под ИИ остаётся SEO, специальные файлы не нужны [17]. Вывод лагеря: отдельной дисциплины AX нет — есть хорошие API, документация и доступность.
3. **«Агент — источник нагрузки и мусора».** tldraw [10], openai/codex и anthropics/claude-code [9], Ghostty [44], curl [46], Hacktoberfest [11]. GitHub отвечает настройками, которые смотрят на объём, право записи и историю участника, а не на «ИИ или нет» [3]–[7].
4. **«Агент — канал, за который должны платить».** Cloudflare: отношение обходов к переходам — от сотен до десятков тысяч к одному [14], [25]; машинный доступ через 402 и x402; подписанные агенты как проверенные боты [15], [47]. Pew показывает, что сводка ИИ почти вдвое снижает переходы [24].

**Противоречия между источниками.**

- **Мусор или норма?** Octoverse: PR с участием агента сливаются чаще, чем без него (≈ 90 % против ≈ 86 %) [1]. Мейнтейнеры закрывают вход [10], [11], [44]. Совместить можно так: Octoverse смотрит на все PR, большинство которых авторы сливают в своих репозиториях; мусор — свойство анонимного внешнего входа популярных проектов. В соседнем досье T4 замеры AIDev середины 2025 года дают обратную картину — эту развилку нужно назвать в эфире, а не сглаживать.
- **Google против Google.** Поиск: llms.txt не нужен [17]; Lighthouse: llms.txt и WebMCP — среди проверок агентной готовности [28].
- **llms.txt читают или нет.** Digital Applied — ноль запросов от четырёх главных краулеров [16]; EZY — единичные запросы OpenAI и Anthropic и регулярные от Meta [26]. Обе выборки малы и смещены; ни одна не измеряет агентов, которые ходят под нераскрытым user agent.
- **Обещание и таблица Netlify.** Текст AXIS говорит о сокращении времени и токенов во всех прогонах, таблица — о росте в одном из них [35].
- **Временная мера стала постоянной.** tldraw обещал вернуть PR, когда у GitHub появятся инструменты; инструменты вышли, а запрет записан в CONTRIBUTING [10].
- **Cloudflare о себе.** Рост обходов «по действию пользователя» — 15× в ключевых выводах и 21× в разделе об ИИ [14]. Роль Moderate у GitHub в заголовке названа общедоступной, а в обновлении того же дня — ещё недоступной [6].

**Где ведущие, вероятно, разойдутся.** Атрибуция ниже опирается на опубликованный конспект S1E10 и расшифровку (строки ≈ 1085–1140 и ≈ 1615–1645 файла `transcript.txt`); меток говорящих в расшифровке нет, поэтому реплику о маркетплейсе и MCP за Евгением закрепляет фраза Александра «вернусь к Жениной», а аналогию с родителем — только конспект. Алексей в S1E10 хотел механизмов, сделанных для агентов, а не копирования действий человека в браузере, и предлагал аналогию «за помощника отвечает тот, кто его запускает и оплачивает». Евгений там же не видел причины убирать подтверждение человеком и заметил, что при интеграции через инструменты продавец видит только отдельные вызовы. Александр рассуждал о банках, которые рискуют стать невидимой инфраструктурой. Отсюда вероятный спор: строить ли для агента отдельный вход (Алексей), сохранять ли человека и данные о пути выбора у себя (Евгений) или считать агентский вход платформенной задачей с допуском и метриками (Александр).

## Вопросы для эфира

1. **Что значит «удобно для агента» и чем это отличается от просто хорошего API и документации?** Ведёт Александр: в S1E2 прозвучала история про внутренние API, которые отдают агентам мегабайтные JSON [41], а его роль Technical Fellow по AI4SDLC — про платформенные контракты. Опоры: принципы инструментов Anthropic и стоимость описаний MCP [32], [33], Markdown по запросу [29], Stripe [31], позиция Google [17].
2. **Как понять, что агент справился с вашим продуктом, если он не пишет в поддержку?** Ведёт Евгений: в S1E9 он рассказывал, как во Flo Health разбирают множество сессий, чтобы найти общие затруднения. Опоры: AXIS и его ограничения [35], практика «пришлите, что сказал агент» [40], доля запросов агентов у Honeycomb [13].
3. **Агент открыл PR или задачу от имени человека — кто отвечает?** Ведёт Алексей: по конспекту S1E10, он предложил аналогию с родителем (в расшифровке нет меток говорящих). Опоры: условия GitHub [19], решение по Amazon v. Perplexity [18], история matplotlib [45], статья 50 Регламента ЕС [50].
4. **Как отличить полезного агента от спама, не закрыв дверь всем?** Ведёт Александр: автор досье об инфраструктуре и снимка 17/300. Опоры: девять настроек GitHub и освобождение по истории [3]–[7], Octoverse [1], публичный список Ghostty [44], curl [46].
5. **Не отрезаем ли мы джунам вход через open source?** Ведёт Алексей как автор образовательной программы; связь с S1E5 «Джун без простых задач». Опоры: GitHub сам признаёт риск для новичков [42]; освобождение по возрасту аккаунта и числу слияний по своей конструкции не помогает новичкам [5] (вывод ведущих, не замер); matplotlib-история началась с задачи «good first issue» [45].
6. **SEO уходит в оптимизацию под агентов: кому достанется интерфейс пользователя?** Ведёт Алексей: в S1E10 он рассказал, что покупатель нашёл его программу через исследование в чате, хотя он ничего специально не делал для OpenAI. Евгений — со стороны продукта, который теряет видимость пути пользователя. Опоры: Pew [24], отношение обходов к переходам [14], логи llms.txt [16], [26], Google [17].
7. **Пускать агентов бесплатно, брать плату или блокировать?** Ведёт Александр (опыт крупного финтеха, тезис о невидимой инфраструктуре из S1E10). Опоры: Monetization Gateway [25], Direct/Intermediary [15], выбор Amazon блокировать агента и ответ суда [18].
8. **Должен ли агент представляться сайту — и сколько он должен рассказать о человеке?** Ведёт Евгений: потребительский продукт о здоровье, чувствительные данные. Опоры: подписанные агенты [47], черновик Web Bot Auth без делегирования [48], испытание `Forwarded` для конечного пользователя [15], решение Perplexity не отправлять user agent [18].
9. **Публиковать ли свой MCP-сервер или навык прямо сейчас?** Ведёт Алексей (в S1E7 он разбирал Agents API, в S1E10 просил механизмов для агентов). Опоры: фонд AAIF [51], [52], спецификация 2026-07-28 [13], уязвимости открытых серверов [54], российский пример MCP Hub [57].

## Кейсы и практики

- **Neon (`vendor`).** Больше 80 % баз создают агенты (данные 2025 года) [12]. Самый частый пример того, что «пользователь» платформы уже не человек.
- **Honeycomb (`vendor`, через анонс MCP).** Почти 20 % ежемесячных интерактивных запросов — от агентов [13].
- **Netlify (`vendor`).** Термин AX (январь 2025 года) [39]; больше 1 000 сайтов в день из ChatGPT на ту дату [39]; анонимный деплой с часом на то, чтобы человек забрал проект [37]; netlify.ai как вход для агентов [38]; открытый инструмент AXIS с участием Auth0 [35], [36].
- **Stripe (`vendor`).** Markdown-версия любой страницы документации, MCP-сервер, каталог навыков по адресу `/.well-known/` и настройка агента одной командой [31].
- **Cloudflare (`vendor` и `measured`).** Markdown по заголовку `Accept` [29], [30]; подписанные агенты и поле Direct/Intermediary [15], [47]; платный машинный доступ [25]; телеметрия Radar [14], [21]. Cloudflare объявила 01.07.2026: с 15.09.2026 для всех новых доменов категории Training и Agent по умолчанию блокируются на страницах с рекламой, Search остаётся разрешённым [67]; распространение умолчания на действующих бесплатных клиентов есть только в пересказе [64].
- **Vercel (`vendor` и `measured`).** Исследование ИИ-краулеров 2024 года [22]; оценка доставки документации через AGENTS.md и навыки [34]; реестр skills.sh — 1 млн навыков за 7 месяцев против 27 месяцев у репозиториев GitHub до той же отметки, 375 навыков (0,04 %) собирают 62 % установок [58]. История из S1E10 о том, как основатель Vercel чинит продукт по транскрипту агента, — непроверенный пересказ [40].
- **GitHub (`vendor`).** Девять настроек входа за 2026 год [3]–[7]; условия о машинных аккаунтах [19]; Octoverse [1].
- **Открытые проекты (`vendor`).** tldraw — PR закрыты с января, правило стало постоянным [10]; Ghostty — раскрытие ИИ и публичный список [44]; curl — закрыта программа вознаграждений [46]; openai/codex и anthropics/claude-code — PR только от соавторов [9]; Hacktoberfest — PR не засчитываются [11]; matplotlib — агент ответил постом на закрытый PR [45] (`secondary`).
- **Cursor Origin (`vendor`).** Хостинг кода под агентов и маркетплейс проверок, ревью и развёртывания [55], [56].
- **Amazon против Perplexity (`regulatory`).** Пример продукта, который пытался не пустить агента: правовой путь через CFAA не сработал, остаются условия использования и техническая детекция [18].
- **Россия (`vendor` и `secondary`).** Yandex AI Studio MCP Hub с шаблонами Контур.Фокус, amoCRM, Трекера, Поиска и SourceCraft [57]. Yandex Commerce Protocol: 27.02.2026 — 3 500 магазинов продают через Алиса AI и Поиск [61]; с 21.08.2026 продавцы без сайта продают через Яндекс Товары [62] — пример того, как ассистент забирает у продавца собственный интерфейс (по досье о платежах; тема T3).
- **WebMCP (`vendor`).** Ранний доступ Chrome с декларативным и императивным API — 10.02.2026 [59]; PayPal показал WebMCP для подготовки покупки 16.09.2026 [60]. Исследовательский аналог — VOIX с тегами `<tool>` и `<context>`, проверенный на хакатоне с 16 разработчиками [65] (`measured`, качественно).
